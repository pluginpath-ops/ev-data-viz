# Optimization ledger

Where we chose the simple path over the fast one. Add a row when you do;
remove it when you fix it.

| Where | What it costs | Fix when |
|---|---|---|
| "Show the math" (`components/calcTrace/*Math.jsx`) | While open, the pass is re-run on every parent render, because the plotted runs, rows and vehicle lists are new arrays each render. One correction, one table row, one vehicle's bars, or one vehicle's simulated week; PerformanceMath also re-runs the chart's entries untraced to list what has bars. Nothing while closed | It lags on a hover |
| `starterSetIds` (utils/setupWizard.js) | resolves specs (`specProvenance`) for every complete vehicle on each starter-set pick in the setup wizard | the fleet passes a few hundred vehicles, or the wizard ships and the pick feels slow |
| Startup EPA read (`EPA_STARTUP_FIELDS`, DataService) | Still brings every certification and its Guide row, ~60% of the EPA bytes left after #501. The Guide row's descriptive columns (division, carline, drive_desc, model_type_desc…) are read only by the EPA views, so they could move to `getEpaDetail`; the overlay columns cannot | The first load is still slow, or the Guide row grows
| Closing the week (`simulateWeek`, utils/costToDrive.js) | A week that cannot close on its own nights is driven again each round (up to `CLOSE_ROUNDS`, 8; usually 1–2), each a two-pass week; the steady-state search drives it again from each lower Monday (up to `CLOSE_ROUNDS` more; usually 1); `leastStopTo` bisects the fast curve (24 calls) for every road stop; Charging Speeds runs it for every level × car × season | Charging Speeds lags on a settings change |
| Time-of-use nights (`chargeInCheapestHours`, utils/costToDrive.js) | Each night is filled cheapest hour first on its own; nothing moves charging between nights (a cheap weekend night topping up more to spare a dear weekday one), so a plan with dear nights is priced a little high. The sort is per night per round, cheap at 24 slots | A reader's plan has nights at different prices, or someone asks why the planner did not shift a night |
| Trip Optimizer leg grid (`OPT_LEG_MI`) | 60–500 mi is 45 stops, twice the old 21, so about 2,500 simulations a vehicle; cells past one charge's reach are null but still run | Opening the optimizer lags, or search stops at the first null leg |
| Phantom drain in the week (`simulateWeek`, utils/costToDrive.js) | Drain is taken from arrival to the plug-in window, and from where the charger stops to midnight; waiting inside the window for cheap hours, and the hours between a night's last charge and the morning, take none (a plugged-in car tops itself up). So a night is sized from the window's opening, and a few tenths of a percent are unbilled | A real-week comparison (the R1T fixture, #590) misses by more than ~0.5% a week |
| Size chart export (`svgToCanvas`, utils/svgRaster.js) | The SVG is copied with every element's computed paint and rasterized after each change, hover included, so Image always has a canvas to read. A few dozen elements a vehicle | Hovering the Size chart with many vehicles selected stutters; then rasterize on Image click instead (useChartPng would need an async source) |
| Size photos on the Size chart (`SizeChartCanvas`, `svgToCanvas`) | Each photo is the full cutout (up to 1,600 px PNG) drawn at chart size, with no smaller rendition; the export fetches each one again to inline it, on every redraw | A selection of many photographed vehicles loads slowly or hover lags; then store a chart-sized rendition beside the cutout, and inline it once per photo |
| Size photo previews on cards and rows (`SizePhotoStrip`) | Each preview is the full cutout (up to 1,600 px PNG) drawn 64 px tall, lazy-loaded; only a page's 24 cards or 50 rows load, and only while a photo check is on. Same missing rendition as the Size chart row above | Turning on a photo filter makes a page slow to fill; then share the chart-sized rendition |
| Size photo baseline (`SIZE_PHOTO_LENGTH_BASELINE_PCT`, constants/sizeChart.js) | One figure (3%, set by eye below the 4.4% median) for every side photo, fitted by hand from the owner's reference list (ids in the constant's comment). No per-body-style or per-lens figure, so a tall truck and a low coupe share it | The reference set grows past ~15 photos, or a body style's photos read consistently off it; then fit a baseline per body style |
| Playback (`playbackPlugins`, utils/chartPlayback.js) | Each frame re-slices every series from its full points and runs a full `chart.update('none')`, re-parsing every dataset; the head of each line is interpolated anew. A few hundred points a test | Playback stutters with many tests selected; then slice by index from the last frame, or clip the canvas where X is time |
